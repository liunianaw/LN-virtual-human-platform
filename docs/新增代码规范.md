# 新增代码规范

适用范围：从 2026-09-21 起新增或本次整改触及的 LN 平台代码。历史若依代码不以格式化或大搬迁的方式追溯整改。

## 分层与目录

业务按功能域放在 `com.ruoyi.system.<domain>`；一个业务域可以有 `controller`、`dto`、`domain`、`mapper`、`service`、`service.impl`。跨域技术能力放在明确的基础设施包，例如 `storage`，不伪装成业务 Service。

| 层 | 只负责 | 不负责 |
|---|---|---|
| Controller | 路由、鉴权上下文、`@Valid`、HTTP 响应 | 业务状态机、事务、直接调用 Mapper |
| DTO | 请求/响应边界和结构校验 | 持久化映射、权限判定 |
| `IxxxService` / `XxxServiceImpl` | 权限规则、业务编排、事务、不变量、错误语义 | HTTP 细节、SQL 拼接 |
| Mapper + XML | 参数化 SQL 与结果映射 | 业务决策、权限和事务 |
| Domain | MyBatis 的持久化数据载体 | HTTP 请求/响应模型 |

本项目新增业务 Service 统一使用 `IxxxService` 接口和 `XxxServiceImpl` 实现，Controller 只依赖接口。`@Service` 只标注实现类。内部技术组件可保持具体 `@Component`，不为它们制造伪 Service 接口。

## 输入、实体与持久化

- 外部请求 DTO 使用 Jakarta Bean Validation；Controller 参数使用 `@Valid`。字段格式、长度、非空等结构约束在 DTO，跨记录、权限、状态和并发校验在 Service。
- 不引入 Lombok 或 JPA 注解来改变当前工程风格。MyBatis Domain 可保留明确的 JavaBean getter/setter；这是 MyBatis 映射契约，不是业务 DTO。
- 继续使用 MyBatis Mapper XML。禁止在同一功能中混入 MyBatis-Plus、JPA Repository 或字符串拼接 SQL。
- 所有 ID、账号归属、枚举、版本号和租约字段在 Service 入口和 SQL 更新条件中双重约束；Mapper 参数使用 `@Param`。

## 事务、权限与错误

- 同一业务事实及其 Outbox 必须在同一数据库事务内提交；网络、MQ、COS 等副作用在事务外执行，并保留可恢复证据。
- Controller 可做入口权限注解/路由保护，但 Service 必须再次保证会影响所有权、官方资源或管理员权限的业务规则，不能靠浏览器路径或布尔参数信任调用方。
- 业务错误使用现有 RuoYi 异常/响应语义；禁止吞掉异常或以 `null` 表示权限、状态和基础设施失败。

## 消息与可维护性

- 消息只携带版本化白名单标识，不能带密钥、大文件、永久 URL 或原始用户内容；消费者按 eventId 与业务状态幂等。
- 修改应限制在当前能力链路：禁止全仓格式化、无关依赖升级、为未来假设增加抽象。每次改动至少运行覆盖其关键风险的最小现有检查。
