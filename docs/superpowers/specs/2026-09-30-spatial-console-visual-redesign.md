# 空灵展台后台视觉重设计执行计划书

前置说明书：[编写与执行规范](../../../执行计划书编写与执行规范.md) · [项目整体说明书](../../../项目整体说明书.md) · [共享后台契约](platform-console-shared-contract.md)。

日期：2026-09-30。版本：0.2。确认状态：完整前端改造待用户确认；已授权独立 HTML 视觉预览及其迭代。以下全量实施草案如与第 9 节最新预览决定冲突，以最新决定为准。

## 1. 当前状态

前端为 `RuoYi-Cloud-Vue3` 的 Vue 3、Vite、Element Plus 单体后台。管理员和开发者共用 `src/layout/index.vue` 的 `Layout`，动态菜单仍由现有权限数据决定；`AppMain.vue` 通过带缓存的路由视图加载页面，`TagsView` 负责已访问页面的切换和关闭。因此，现有后台骨架已经满足“左侧菜单不变，点击菜单更新独立展示窗口”的交互基础。

目前页面外壳、导航、菜单和 Element Plus 表面主要使用白色或深色实底、常规阴影和多处分散的硬编码色值。全局入口为 `src/assets/styles/index.scss`，主要相关样式在 `variables.module.scss`、`sidebar.scss`、`ruoyi.scss`，局部外壳在 `src/layout/`。已有主题切换和 `prefers-reduced-motion` 降级逻辑，必须保留。

工作树已有角色制作、用量与 Webhook 的未提交业务改动。该计划不修改这些业务接口、页面数据、路由或权限，实施时仅在与该计划明确重叠的全局视觉文件中增量适配，并避免覆盖现有页面改动。

## 2. 目标与边界

在不改变 RuoYi 现有导航布局、路由、标签页、权限、表单字段、接口或业务文案的前提下，形成一套可同时用于管理员和开发者的“云雾玻璃展台”视觉系统：

- 保留左侧菜单、顶部栏和标签页。每个路由页面在内容区内呈现为带安全边距的独立展示窗口，菜单或标签切换只更新该窗口的内容。
- 使用冷灰蓝、雾白和单一的天蓝强调色，借鉴参考图的留白、层次、半透明材质和柔和远景，但不复制其中角色、美术、图标、文字或游戏 UI。
- 提供浅色和深色两套语义令牌。浅色为主要工作模式，深色保持同一空间材质和层级，不能退化为纯黑实底。
- 统一按钮、输入、表格、卡片、抽屉、弹窗、分页、空状态和加载状态的边界、圆角、阴影、焦点与悬停反馈。

本计划不包含重写信息架构、修改菜单名称或 URL、替换品牌标识、引入新的组件库、重写业务页面功能、执行真实外部调用，或将参考图中的游戏角色作为平台视觉素材。

## 3. 已确认决策

| 决策 | 结果 |
|---|---|
| 布局 | 管理员和开发者继续使用同一 RuoYi `Layout` 和动态菜单，保持左侧菜单、顶栏、标签页的功能位置。 |
| 内容呈现 | 以 `AppMain` 为统一页面展台容器。桌面端为外侧留白加内层展示窗口，移动端退化为全宽可滚动内容，避免窄屏玻璃边框挤压业务表单。 |
| 视觉语言 | 采用 Web 端毛玻璃近似实现，不声称使用 Apple 原生 Liquid Glass。材质由半透明表面、内高光、低对比边框和蓝灰阴影构成。 |
| 色彩 | 唯一非语义强调色为天蓝色。成功、警告、危险等保留 Element Plus 语义色，以免把业务状态伪装为装饰。 |
| 动效 | 仅为路由展台切换、菜单/按钮反馈和必要的骨架加载加入短时 `transform` 与 `opacity` 过渡。遵从 `prefers-reduced-motion`，不使用滚动监听、无限动画或视差。 |
| 视觉资源 | 背景使用新生成的无人物抽象云雾环境图或同等质量的许可资源，并保留 CSS 渐变降级。不得使用参考图截图或其拆出的美术资源。 |

仍需用户确认：以本计划的视觉范围作为“全面前端页面优化”的实施边界，并授权后续生成一张仅供平台背景使用的原创抽象环境图。

|---|---|---|
| `src/layout/index.vue` | 组合侧栏、固定头部、标签页与页面主区，处理桌面和移动端侧栏状态 | 保留结构和状态，只添加壳层语义类与背景承载。 |
| `src/layout/components/AppMain.vue` | 带 `keep-alive` 的路由视图，现有淡入切换和滚动边界 | 在不改变缓存键、iframe 或版权组件的前提下，加入展示窗口包裹层和路由切换视觉。 |
| `src/layout/components/Navbar.vue`、`Sidebar/`、`TagsView/` | 菜单、账户操作、主题切换、页面标签 | 保留全部事件和组件，只重做高度、材质、激活态、焦点态及窄屏反馈。 |
| `src/assets/styles/index.scss`、`variables.module.scss` | 全局主题变量与 Element Plus 覆盖入口 | 建立浅色和深色的空间语义令牌，并把组件表面统一改为消费令牌。 |

不新建全局状态，不引入动画或 UI 依赖。现有 `@vueuse/core`、Vue 路由缓存、主题设置和 Element Plus 图标继续复用。

## 5. 完整流程

1. 用户登录后，既有权限装配动态菜单并进入 `Layout`。该流程不因视觉改造改变。
2. `Layout` 在应用壳层铺设低对比云雾背景和可访问的实底降级层，侧栏、顶栏和标签栏作为同一套半透明导航材质浮于其上。
3. 点击菜单或标签继续走现有路由与 `TagsView` 逻辑。`AppMain` 的路由视图在桌面内容区获得统一外边距和展示窗口表面，缓存和 iframe 的行为保持不变。
4. 每个业务页面继续渲染既有 Element Plus 表格、表单和弹层；全局令牌让常见容器自动获得一致的玻璃表面、分层边框、焦点环和蓝灰阴影。业务页面保留自己的信息结构和数据密度。
5. 系统主题切换仍调用现有设置存储。浅深主题替换同名语义令牌，用户设置和现有视图过渡继续有效。减少动效或减少透明度时，毛玻璃退化为高对比实底，所有交互仍可读可用。

失败与恢复：背景资源加载失败时使用 CSS 云雾渐变；不支持 `backdrop-filter` 或用户偏好降低透明度时使用不透明窗口表面；窄屏时移除过度装饰和桌面外边距。上述降级不影响菜单、路由、缓存、表单提交或权限结果。

## 6. 视觉契约

### 6.1 令牌

| 类别 | 浅色模式 | 深色模式 | 约束 |
|---|---|---|---|
| 环境底色 | 冰雾蓝灰 | 深蓝灰雾面 | 使用多层低饱和径向渐变和背景图，不使用纯白或纯黑。 |
| 主强调色 | 天蓝 `#238fc4` | 高明度天蓝 | 只用于选中、主操作、焦点和可交互强调。 |
| 展台表面 | 雾白半透明 | 蓝灰半透明 | 必须有内高光、1px 半透明边界和实底降级。 |
| 文字 | 深靛灰 | 冷白灰 | 正文及表单标签满足 WCAG AA，对比度优先于透明感。 |
| 圆角与阴影 | 页面展台 20px，组件 12px，紧凑控件 8px | 同左 | 阴影带蓝灰色相，不使用纯黑厚阴影。 |

### 6.2 组件和响应式约束

- 页面展台仅包裹路由页面内容，不遮挡抽屉、全屏模式、iframe 或全局通知层。
- 表格头、筛选区、分页与详情卡按信息层级区分，不把所有数据都塞进相同的大卡片。
- 菜单选中态为柔和天蓝透镜面，不能只依赖颜色区分，须同时保留文字权重、背景和键盘焦点。
- 桌面端内容区最小外边距为 24px，宽屏可提升至 32px；小于 992px 时降为 12px，小于 768px 时取消展台阴影并使用全宽表面。
- 所有动效只允许 `opacity` 和 `transform`，时长不超过 220ms。`prefers-reduced-motion: reduce` 下不执行路由入场和悬停位移动画。

## 8. 验证与验收

代理的最小静态验证：

1. 在 `RuoYi-Cloud-Vue3` 运行 `npm run typecheck`。
2. 审核样式令牌、主题切换、缩小动效、透明度降级和 768px、992px 响应式规则。
3. 检查改动范围和 `git diff --check`，确保不包含参考图、凭证、构建产物或无关业务文件。

用户终点验收，须在授权启动本机前端后执行：

1. 以管理员和开发者账号分别登录，确认仍共用同一后台壳层，菜单差异仍由权限决定。
2. 在角色制作、应用配置、运营记录和用量页面之间切换，确认菜单或标签页只更新中央展示窗口，滚动、缓存和弹层正常。
3. 在浅色、深色、桌面和窄屏下检查文字、按钮、表格、抽屉和对话框的对比度、溢出与可点击性。
4. 用系统的降低动效偏好复验切换无动画，用不支持透明效果的浏览器或开发工具验证实底降级。

默认不启动服务、不登录浏览器、不调用外部服务，也不执行任何付费操作。
