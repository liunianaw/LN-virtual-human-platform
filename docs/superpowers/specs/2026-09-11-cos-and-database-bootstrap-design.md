# COS 与 MySQL 初始化设计

**任务：M1-DB-001**
**日期：2026-09-11**
**状态：已获负责人执行授权，待实施计划评审**

## 目标与边界

- 为本机 MySQL 8.0 创建 `platform_db` 和 `session_db`，按[数据库设计说明书](../../../数据库设计说明书.md)及[结构化字段字典](../../database/schema-draft.json)落地 48 张业务表：平台库 35 张、会话库 13 张。
- 同时在 `platform_db` 建立运行所需的若依系统/兼容表，但不导入上游演示账号、部门、菜单、默认密码或已裁剪模块的数据。
- 让 system 服务按腾讯云 COS 私有桶 `ln-virtual-human-platform-1411676391`、广州 `ap-guangzhou` 运行，读取操作使用短期签名 URL。
- 不在仓库、Nacos 模板、数据库或日志保存 SecretId、SecretKey、登录密码或其他真实秘密；不执行 `DROP DATABASE`、`DROP TABLE`、Flyway clean 或重置已有数据。

## 设计决策

### 数据库迁移

1. `RuoYi-Cloud/ruoyi-modules/ruoyi-system/src/main/resources/db/migration/` 保存平台库的版本化 Flyway SQL；新增 session 模块前，`RuoYi-Cloud/sql/` 保存会话库的受版本控制初始化迁移及由本机初始化命令执行的入口。两者均以同一结构化字段字典为唯一字段/索引来源，避免人工维护第二套业务 DDL。
2. 初始化过程先创建两个带 `utf8mb4`、InnoDB 默认值的数据库，再应用平台库和会话库迁移。迁移必须可重复执行：已应用版本由迁移历史记录识别，禁止以重建或删除数据库实现“重复”。
3. 若依原始 `ry_20260417.sql` 仅用作表字段兼容参考，不能直接导入，因为它含有破坏性 DDL 和与本项目不符的示例数据。系统表创建、项目字段变更、最小角色/菜单种子数据将作为受控迁移的一部分。
4. 完整逻辑模式先落地为 schema；未实现的业务服务不会因此被标记为已联调。迁移完成后仅验证数据库结构、迁移可重放性和现有 system 模块可构建性。

### COS 本地秘密配置

1. 保留现有 `CosObjectStorage` 和腾讯云官方 SDK；不新建上传协议、文件服务器或另一套对象存储抽象。
2. 在 system 的 `application.yml` 中固定非秘密连接信息（启用开关、区域、桶名、签名 URL 时长），并导入一个可选的本地 YAML 文件。
3. 该本地文件固定为 `RuoYi-Cloud/ruoyi-modules/ruoyi-system/config/local/cos.yml`，通过 `.gitignore` 排除；仓库只提供不含凭据的 `cos.yml.example`。负责人将在实施完成后手工把 SecretId 与 SecretKey 填入忽略文件，服务重启后生效。
4. 配置未填写时，COS 保持禁用或在上传时给出明确配置错误；不以空字符串或伪密钥启动已启用的 COS 客户端。

## 执行顺序与验证

1. 生成并静态校验 DDL（表名、列数、索引/外键引用、字符集及幂等性）。
2. 使用本机 MySQL root 账户创建并初始化两个空库，记录实际表数与 Flyway 历史；第二次运行只校验/跳过既有迁移。
3. 配置 COS 的非秘密参数、忽略规则及本地样例文件。交付时明确手工密钥文件路径，不读取、打印或提交该真实文件。
4. 待负责人填写本地文件后，使用一个隔离测试对象执行上传、签名读取和删除；不把测试对象、签名 URL 或密钥写入数据库和日志。

## 风险与回退

- 初次建库是持久化写入；执行前再次确认目标库不存在，失败后保留错误和迁移历史，不使用删除重试。
- 腾讯云凭据只从负责人指定的 CSV 读取一次以创建本地文件样例/验证格式，真实值不进入提交或代理报告。若已暴露过，应在腾讯云控制台轮换。
- 私有桶的浏览器预览另需 COS CORS 与真实访问测试；本任务只配置服务端 SDK 和签名 URL，不能将配置存在等同于云端联通。
