## 1. 目标与边界

用户以自己的参考图创建八动作角色，查看真实进度、预览并确认可用，之后在自己的平台应用或外部项目中使用。角色、源图、制作任务与候选版本默认私有，其他普通用户不可查询、下载、修改或引用。

“发布”在现有后端表示版本进入 PUBLISHED；用户界面应称“确认可用”，不能让用户误以为上传到公共库。**私有版本可用，不改变私有归属。** 本流程不含私有转公共、账号间转让、声音制作或自动恢复旧任务的用户操作。

## 2. 前置条件与可信输入

- 有效登录用户具有私有资产操作权限；账号由登录态解析，不信任请求中的 accountId/ownerAccountId。
- 至少一个已启用的制作服务；用户选择服务，不提交厂商密钥或任意模型地址。
- 文件、任务、版本、应用模块共享同一资产授权判断。用户不能先借公共角色读取权限，再下载管理员源图。
- 角色制作次数不重新设限；重复提交防重与真实调用记录保留。遇到旧额度代码，应核对实际 SQL 行为，不把旧错误文字当作已恢复限额。

## 3. 用户完整执行流程

| 步骤 | 用户操作与接口交接 | 服务端责任与持久结果 | 页面应体现 |
|---|---|---|---|
| U1 进入制作页 | GET `/asset/generation-services`，选中 serviceId | 返回可用服务及 revision，字段见共享 C1 | 真实可选列表，无服务时说明原因 |
| U2 上传参考图 | POST `/asset/files`：file、rightsNoticeVersion、rightsConfirmed | 校验真实文件格式/大小/尺寸，保存本人私有文件，返回 fileId | 上传完成后才能创建；readUrl 仅临时预览 |
| U3 新建私有制作 | POST `/asset/generation-tasks`：sourceFileId=fileId、officialServiceId=serviceId、name、requestId | 校验文件归属；固定服务快照；事务建立角色、候选、任务、八动作与 Outbox | 保存 Task 返回的 taskId、avatarId、avatarVersionId，不能互相替代 |
| U4 查询制作进度 | GET `/asset/generation-tasks/{taskId}`；刷新页面后列表恢复显示 | 服务端按任务归属返回进度、阶段及失败原因 | 离开页面不取消任务；未发厂商请求与已响应后处理要分清 |
| U5 自动生成与加工 | 与管理员流程共享 C2/C3，无新增用户输入 | 回执先保存；下载/加工/上传/汇总独立可追踪；安全恢复不重新付费 | 下载问题由系统内部有限恢复；不要求用户判断该恢复哪个动作 |
| U6 动作选用与整套预览 | 动作完成即用第10节结果preview，selection确认，不满意调用单动作generations；八项确认后assemble，再GET整套版本preview | 核对本人版本/动作/result关联；独立预览不要求REVIEW；整套汇总成功才REVIEW | 八卡片逐项播放和重做，保留旧结果；不能等全部结束才给预览 |
| U7 确认为本人可用 | POST 相同版本路径 `/publish`，visualAccepted=true、reviewNote | REVIEW → PUBLISHED，保持 PRIVATE 和本人 owner；记录人工确认 | 私有角色库显示可用，不出现在公共库 |
| U8 绑定自己的应用 | 交给应用模块 avatarId、versionId，不交源图URL | 应用模块验证本人拥有应用和私有版本，再创建引用 | 本人可配自己的声音并使用；声音是另一流程，不在此重复实现 |
| U9 重新制作或删除 | 同角色重新制作使用新requestId和目标avatarId；删除走 DELETE `/asset/avatars/{avatarId}` | 按FR-AV-06创建同角色新版本与新任务，不覆盖旧版；当前接口缺少目标角色字段/新版本入口，需补齐；删除检查Application、可恢复Session和活动制作 | 明确是新制作；被引用不能删除时解释原因，而不是静默失败 |

此表中的既有路径存在不等于完整流程可用。公共流程文件第2节记录的汇总/恢复等缺口同样阻断本流程。

## 4. 请求、返回与参数来源

请求/响应字段唯一来源为共享 C1；本流程追加以下私有语义，不能以文字说明代替后端条件：

| 数据 | 来自哪里 | 传到哪里 | 不变量 |
|---|---|---|---|
| 当前账号 | 已验证登录态 | 文件归属、任务创建、版本授权、应用授权 | 前端不能任意指定；用户B不能替换为A |
| sourceFileId | 本人上传返回 fileId | 创建任务 DTO → 持久任务 → Worker签名参考图 | 必须是本人可用源文件，不能拿公共 atlas 文件ID冒充参考图 |
| officialServiceId | 可用服务列表的 serviceId | 创建时读取固定服务配置 | 客户端不能决定 endpoint/秘密；后续动作不能漂移到新默认模型 |
| requestId | 前端一次新建操作生成 | 任务幂等键与参数摘要 | 同一次网络重试不换值；明确重新制作才换值 |
| taskId | 创建返回 Task.taskId | 任务详情、Outbox及执行追踪 | 不作为角色或版本ID使用 |
| avatarId/版本ID | Task.avatarId/avatarVersionId | 预览路径 avatarId/versionId → 应用固定引用 | versionId 必须属于该 avatarId；归属由数据库校验 |
| readUrl/atlasUrl/manifestUrl | 已鉴权文件读取 | 预览或运行时加载 | 短期凭证，不保存成永久引用；过期重新授权读取 |

私有创建示例（目标中已有字段，示例 ID 不代表实际数据）：

```json
{
  "sourceFileId": "123456789012345678",
  "officialServiceId": "123456789012345679",
  "requestId": "private-avatar-example-01",
  "name": "我的角色"
}
```

请求中没有 accountId、visibility、providerKey。如果前端夹带 OFFICIAL 或其他账号字段，应拒绝敏感越权字段或明确不参与领域决策，并验证最终落库仍为本人私有；不能依靠 DTO 忽略字段掩盖通用接口中的授权漏洞。

返回 Task 后，调用预览时使用 `Task.avatarVersionId` 填入 URL 的 `versionId`。预览返回 `Preview.versionId`；应用统一采用这一个版本值。业务 ID 全程字符串，不经过 JavaScript Number。

## 5. 与管理员及其他模块交叉时如何复用

| 交叉模块 | 共享部分 | 私有差异/禁止复用方式 |
|---|---|---|
| 管理员公共制作 | 文件验证、模型调用、提示词、六帧加工、Worker状态机、正式包、播放器 | 不复用公共发布权限作为私有授权；同一引擎接收服务端可信的归属上下文 |
| 平台服务配置 | 可用服务查询与任务服务快照 | 用户不可修改官方配置或获取密钥；服务变更冲突策略见共享C2 |
| 文件管理 | COS 私有存储、签名读取、哈希与清理 | 公共目录权限不覆盖本人源图隐私；文件所属账号不能为了读取方便改写 |
| 应用/开发者接入 | 正式已发布版本解析、SDK播放、固定版本引用 | 要同时检查应用拥有者与私有资产拥有者；有效会话凭证不等于任意资产读取权 |
| 声音配置 | 应用组合时分别引用 avatarVersionId 与 voiceVersionId | 角色制作不创建声音，不复制声音凭证；分别校验私有/公共可用范围 |
| 任务与运行管理 | 相同错误阶段、回执、attempt、租约与恢复规则 | 普通用户只读本人安全错误摘要，不返回厂商密钥、原始回执或别人的任务 |

实现建议：抽取/沿用同一资产授权服务，区分“可读取”“可绑定”“可修改”，而非统一调用 requireOwnedPublishedVersion 后到处加管理员绕过。本人私有可读可修改，已发布后可绑定；他人公共已发布可读可绑定不可修改；他人私有全部拒绝。具体方法签名待代码适配，不宣称现有方法已经支持该矩阵。

## 6. 异常、管理和不变条件

- 网络重复提交：同键同参返回同一任务；同键异参返回冲突。用户看到的“新制作”总是新任务，不能偷偷接到旧失败任务。
- 下载失败：同一任务保留厂商成功事实，仅恢复下载；生成结果未知不自动发起新收费请求。完整规则引用共享 C3。
- 部分动作成功：保留原图与成功文件，显示真实完成数量；不是整套可用，不允许提前绑定。恢复是系统内部机制，不增加“明天先继续旧任务”的要求。
- 人工不满意：不确认可用，候选不进入应用选择；仅重做指定动作并保留满意结果，接口按公共计划第10节。已发布角色再次制作形成同角色新版本，不改旧版本。第一阶段不增加复杂审批或修图流程。
- URL过期：重新鉴权读取；别人复制到短期签名URL的有效期内风险需通过短TTL和避免泄露控制，不能宣称签名URL即时撤回绝对可靠。
- 删除：先鉴权并检查引用/制作状态，再标记删除和异步清理；不得删除公共角色原版，Application或可恢复Session引用时均返回冲突，仅解绑当前应用不足以永久删除。清理故障保留可追踪状态，不以接口返回成功代表所有文件已消失。
- 平台管理员运维查看用户私有内容的权限是独立问题，本稿不默认授予全量素材浏览或将用户资产转公共的能力。

## 8. 用户终点验收

- [ ] 用户A真实新建一套角色，完成八动作、整套包与逐动作预览；人工确认后仅本人可用。
- [ ] 用户B在列表、详情、预览、文件读取、绑定、发布、删除各入口均不能操作A的私有资产，知道ID也不能绕过。
- [ ] A可选择公共角色及本人私有角色；自己的声音保持自己的配置，不随角色公开。
- [ ] A在自己的应用中加载固定私有版本；刷新/短期URL更新后仍可正常使用，B的应用不能引用该版本。
- [ ] 重新制作一次产生新任务，不覆盖已有可用角色；用户不需要先处理旧任务。
- [ ] 对被引用资产删除得到清楚提示；允许删除后的状态与实际清理情况可核对。

执行顺序：沿用确认后的共享契约 → 复用制作引擎并补私有管理/引用授权 → 主代理逻辑验证 → 两用户最短联调 → 用户实际制作与预览验收。不把管理员已跑通当作私有隔离已通过；相同引擎检查证据可复用，不重复付费制造同类故障。

## 9. 已定规则与剩余细化

按《项目需求说明书》FR-AV-06，私有重新生成形成同角色新版本，验收后切换；不是“另建角色还是新版本”待选择。数据库6.8～6.10使用 `p_avatar.account_id` 和 `visibility=PRIVATE/OFFICIAL`，版本用 `avatar_id/version_no` 关联，动作引用 `avatar_version_id`。当前入口每次新建角色是实现缺口，不是修改需求的依据。

更新Application后，新Session使用新配置；已有/恢复Session保持旧配置。实时停用限制优先于旧快照，删除必须检查可恢复Session引用。两份说明书采用同一规则，依据详见公共说明书第9节。

单动作制作/重做、结果选用、放弃本轮选用、恢复和整套汇总按公共计划第10节实施；新版本、发布并发及停用行为使用同一契约。旧接口标“现有”是实现盘点，必须兼容接入新引擎。主代理编码时完成DDL/DTO适配，不以表尚未新增为理由绕过结果历史、权限或费用边界；业务范围变更才重新讨论。
